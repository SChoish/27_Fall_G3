2026-11-28 설계안. 기준 코드 `684a76424fed6f882de7fa405e842e6279cdd86a`. 실행 전 상태다. 지난 결과와 FoM의 전기적 제약은 [인수인계](HANDOFF_20261128_KO.md), 선택 정책 구현은 [direct_surrogate_gate.py](direct_surrogate_gate.py)에 있다.

## 판별할 질문

직전 비대칭 2출력 회로의 5% 목표에서 세 방법 모두 6/6 성공했고 최초 확인까지 제한평균 SPICE 횟수는 고정 소스 MLP 37.33, 직접 PPO 47.00, 무작위 head 55.00이었다. 서로 다른 폭을 제안한 시점만 보면 SKY130 타깃에서는 PPO가 소스 head를 30/30번, GF180 타깃에서는 최신 head를 24/37번, 과거 head를 13/37번 골랐다. 전이 방향마다 별도로 학습한 actor가 있으므로 지금 결과로는 소스 학습에서 얻은 head 선호, 탐색 진행도, 타깃 측정값의 기여를 구별하기 어렵다.

1. **실용 성능** — 학습된 선택기가 고정 소스 MLP + 타깃 잔차 GP보다 새 배선에서 목표까지 필요한 SPICE를 줄이는가?
2. **선택의 기전** — 같은 PPO 학습에서 개별 head의 예측과 불확실성을 actor가 볼 때 추가 이득이 있는가?

## 비교군

| 방법 | 매 결정에서 다음 설계 폭을 선택하는 방식 |
|---|---|
| `mlp200` | 고정 소스 MLP와 타깃 잔차 GP가 고른 후보를 평가한다. 실용 성능 기준선이다. |
| `random_snapshot` | 사용 가능한 head 하나를 균등 추출하고 그 head의 후보를 평가한다. |
| `ppo_stage` (신규) | PPO actor가 소스·최신 여부, head가 학습에 쓴 관측의 비율, 탐색 진행도와 목표에 해당하는 기존 입력만 보고 head를 고른다. |
| `ppo_snapshot` | 위 입력에 각 head가 제안한 설계의 예측 마진, head 간 예측 합의·분산, GP 불확실성, 현재 목표 격차와의 상호작용까지 제공한다. |

`ppo_stage` 구현은 options()의 10개 열 중 0부터 센 3–7번을 **소스 학습과 타깃 추론 양쪽**에서 0으로 만들고 재학습한다. 0, 1, 2, 8, 9번과 기존 동률 처리 순서를 유지한다. critic에는 양쪽 모두 기존 학습 상태를 제공한다. 네 비교군의 surrogate와 GP에는 기존 방식대로 유료 타깃 측정이 들어간다. 입력 제한은 오직 새 actor에 적용한다. 동일한 이력을 재생했을 때 두 PPO의 후보 폭과 head별 제안이 정확히 같은지 SPICE 호출 없이 먼저 검사한다.

양방향 모두 반대편 PDK의 동일 200회 소스 기록으로 학습한다. 직접 PPO와 같은 3개 actor seed(41–43), 20 × 24개 소스 에피소드, clip 0.2, epoch당 네 번 갱신, 같은 후보·웜업 난수 규칙을 쓴다. 타깃에서는 세 actor의 로짓을 평균한 뒤 argmax로 선택한다. 타깃 결과로 head 규칙이나 actor를 튜닝하지 않는다. 이 실험이 추정하는 것은 이 학습 절차에서 **측정에 의존하는 actor 입력을 추가한 효과**다.

## 미리 고정할 타깃과 예산

| 회로 | Circuit.parents | outputs | nominal sizes |
|---|---|---|---|
| A · 입력과 앞단을 공유하는 4단·6단 출력 | (-1,0,1,2,2,4,5) | (3,6) | (1,1.4,2,2.8,1.6,2,3.1) |
| B · 독립 입력의 4단·6단 출력 | (-1,0,1,2,-2,4,5,6,7,8) | (3,9) | (1,1.3,1.8,2.7,1,1.25,1.55,1.9,2.3,3) |

두 회로에 SKY130·GF180을 각각 적용한다. 출력 부하 배수는 균형 (1,1)과 비대칭 (0.75,1.5)이며 상호 정전용량은 2.5 fF로 고정한다. 회로 이름은 집계용이다. 알고리즘에 소자 역할이나 조정 방향을 제공하지 않는다. 전기적 목표의 달성 가능성은 미검증이다. 실행 전에는 nominal deck·측정 정의·범위만 확인하고 타깃 결과를 보고 회로를 골라내지 않는다. 회로 A와 B는 소자 수도 달라 공유 앞단만의 효과를 추정할 수 없다.

- 1차는 최악 EDP 5% 개선 + 기존 전기 제약의 정밀 확인이다. 회로 2 × 타깃 PDK 2 × 부하 2 × seed 12 = **방법당 96회 독립 시작, 방법 간 대응 비교**. 한 PDK·회로·부하 내에서 seed 12개를 사용하고 PDK 간에는 대응 seed를 재사용한다. seed는 회로 i, 부하 j(각 0,1), k=0,…,11에서 2000 + 100i + 20j + k다.
- 한 궤적의 상한은 **100 SPICE eval**. 한 설계의 한 코너 transient를 1회로 센다. nominal, 무작위 웜업 네 설계, 개발·독립 확인·정밀 확인, 실패한 시도까지 모두 기록한다. 같은 시작 조건과 웜업을 네 방법에 대응시킨다. 소스 학습용 200회는 전이 방향별로 따로 보고한다.
- 5% 시험의 최대 타깃 비용은 4 × 96 × 100 = **38,400 eval**이다. 10%는 같은 설계로 별도 실행할 수 있는 2차 시험이다. 추가 상한은 38,400이며, 5%에서 멈춘 궤적을 10% 실패로 세지 않는다.

## 분석과 후속 결정

각 시작에서 T는 첫 정밀 확인까지 누적 eval, 비용은 min(T, 100)이다. 미달과 마지막 100회째 성공은 동일 비용이므로 hit도 함께 보존한다. 8개 조건에 같은 가중치를 주고, 전체 및 PDK별 성공 분자/분모, 제한평균 비용, 1–100회 누적 달성 곡선을 낸다. 성공한 실행만 남기는 평균은 쓰지 않는다.

주 비교는 PPO − mlp200, 기전 비교는 PPO − ppo_stage다. 차이가 음수이면 직접 PPO가 빠르다. 동일 회로·부하 안에서 seed 블록을 10,000회 재표집하고 두 PDK와 네 방법을 같이 묶어 각 차이의 95% 구간을 구한다. 두 구간은 비교별 구간이다. 성공이 바뀐 대응 쌍도 양방향으로 집계한다. 불확실성의 범위는 고정한 두 회로에서 시작점을 바꿀 때까지다.

- `ppo_snapshot`의 비용 차이 구간이 `mlp200` 대비 0 아래이고 관측 성공 수도 유지되면 이 시험군에서 다음 기본 방법으로 채택한다. 방향별 결과가 엇갈리면 전이 방향별로 보고한다.
- `ppo_stage` 대비 비용도 같은 방향으로 줄면 측정 기반 선택이 기여했다는 근거로 쓴다. 구간이 0을 포함하면 기여 크기는 미결이다. stage만으로도 고정 MLP를 이기면 더 단순한 선택기로서 후속 확인한다.
- 두 PPO가 고정 MLP에 못 미치면 다음 개발 축은 **후보 생성**이다. 소스 elite 매핑 유무 × adaptive metric 유무의 2×2를 고정 선택기에서 비교한다. 독립 타깃을 남겨 이번 시험군에서 얻은 아이디어를 다시 검증한다.

궤적에는 회로·PDK·부하·seed·arm·누적 호출·hit를 남긴다. 선택 시점별로 사용 가능 head의 학습 종료 위치, head별 제안 폭 식별자, actor 입력과 로짓, 선택한 head를 저장한다. 결과가 나온 뒤 **서로 다른 폭이 제안된 결정 수 / 전체 결정 수**와 그 시점의 head 선택을 보고한다. 자주 선택된 head가 성과를 개선했다고 선택 빈도만으로 판정하지 않는다.

재개 시 첫 작업은 신규 arm과 두 타깃 등록, 마스킹 및 후보 일치 검사, run manifest 고정이다. 이 문서 작성 시 신규 arm 구현과 SPICE 실행은 시작하지 않았다.

## 실행 방법 · 2026-11-28 구현

브랜치 `research/transferable-lane-monitor`의 저장소 루트에서 실행한다. Python 3.10 이상과 NumPy, 기존 실험과 같은 Node 24와 ngspice ESM 파일을 사용한다. `GF_MODEL`과 `NGSPICE_MJS`는 기존 실행에서 사용한 절대경로로 설정한다. [시뮬레이터와 모델 버전](../README.md) · [GF180 모델 준비](../domain_transfer/prepare_gf.py)

```bash
cd campaigns/transferable_lane_monitor/sizing/device_transfer
python stage_transfer_check.py
python stage_transfer_run.py \
  --sky ../../../../adc_driver/models/sky130_1v8_tt.spice \
  --gf "${GF_MODEL:?set GF_MODEL}" --wasm "${NGSPICE_MJS:?set NGSPICE_MJS}" \
  --node "$(command -v node)" --out runs --workers 4
```

위 명령은 5% 목표 384개 궤적을 등록한다. 각 arm은 자기 궤적에서 실제 SPICE를 호출하고 성공을 정밀 확인하는 즉시 멈춘다. 모델 학습은 이미 끝났으며 3개 seed × 2개 전이 방향의 신규 가중치는 `stage_transfer_weights.json`에 있다. 소스에서 다시 학습해 비교하려면 `python stage_transfer_check.py --retrain`을 사용한다.

동일 명령을 재실행하면 완료된 궤적은 건너뛰고 중단된 궤적에서는 디스크에 기록된 마지막 코너부터 이어간다. 코너 결과를 쓰기 전에 프로세스가 강제 종료된 경우에는 해당 코너를 다시 실행할 수 있다. 다른 arm의 결과는 재사용하지 않는다. 측정 실패도 호출에 포함한다. nominal 기준 자체를 측정할 수 없으면 해당 실행은 중단 원인과 함께 남긴다.

완료 시 `runs/stage_transfer_95/summary.json`에 방법별 성공 수, 제한평균 비용, 누적 달성 수, PDK별 대응 차이와 95% 구간, head 선택 집계가 저장된다. 같은 폴더의 `manifest.json`에는 조건·seed·시뮬레이터 지문이 있다. 개별 궤적 JSON의 `trace`가 코너별 전기 측정, `actions`가 웜업 이후 각 head의 제안과 선택이다. 집계만 재실행하려면 `python stage_transfer_report.py runs/stage_transfer_95`를 쓴다. 별도 10% 시험은 실행 명령에 `--goal 0.90`을 추가한다.

구현 검산에서 8개 새 조건의 nominal 4코너씩 총 32회가 측정·검사를 통과했다. 기존 회로에서 수집한 704개 결정(서로 다른 폭 제안 644개)에 대해 두 PPO의 후보 ID가 일치했고, 신규 actor의 입력 3–7열이 모두 0이었다. 기존 비대칭 SKY 회로의 별도 seed 997에서 네 방법의 실제 SPICE 호출 184회를 원자료로 재집계했다. 완료 코너 9개에서 중단을 모사한 뒤 같은 궤적이 복원되는 것도 확인했다. 이 검산은 새 회로의 96개 대응 시작점과 분리했다.

본실험 실행에서는 위 명령에 `--compiled --workers 8`을 적용했다. 기존 프로젝트의 ngspice worker가 컴파일된 WASM 모듈만 재사용하며, 매 유료 코너마다 새 시뮬레이터 인스턴스를 만들어 transient를 계산한다. 회로 해나 이전 궤적 측정값은 공유하지 않는다. 이 실행을 재개할 때는 `--compiled`를 유지한다.
