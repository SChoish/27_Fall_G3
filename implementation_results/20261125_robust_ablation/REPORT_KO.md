# G3 제약 탐색 개선 실험 — 2026-11-25

기존 회로, 설계 변수와 범위, ADC 1 mV 및 D2D 마진 0.08 / overshoot 0.2 기준을
유지했다. 세 optimization seed에서 기존 BO, 최악 제약 GP, 별도 개발 입력 검증을
분리해 비교했다. **최악 제약 GP로의 일괄 교체는 채택하지 않는다.** ADC에서는
에너지가 증가했고, D2D에서는 실패가 남았다. 예산 내 검증은 일부 실패를 걸러냈지만
64비트 검증만으로 128비트 패킷의 품질을 보장하지 못했다. 이를 반영한 **128비트
검증 + 기존 BO는 별도의 새 시험에서 3/3 seed, 48/48개 패킷을 통과했다.** 다만
실패 설계까지 포함한 기존 BO 평균 대비 에너지가 13.53% 높다. 품질 개선을 확인했으며
추가 에너지 절감은 확인하지 못했다.

## 1. 수정과 비교 계약

- 기존 `ConstrainedSearch`는 그대로 기본값으로 유지했다. 코드 분리 전후 3 seed ×
  20 proposal이 완전히 일치했고, 실패한 시뮬레이션을 포함한 반경 갱신도 같았다.
- `MaxConstraintSearch`는 `h(x)=max_j g_j(x)`를 예측한다. `h<=0`과 개발 제약 전체
  통과는 동치다. 기존의 제약별 확률 가중 점수와 비교하기 위한 실험적 대안이다.
  Gaussian surrogate 확률의 보정이나 새 입력 분포의 통과 확률은 보장하지 않는다.
- 검증 후보는 개발 에너지가 가장 낮은 두 점과 측정된 최악 제약 여유가 가장 큰
  한 점이다. 중복은 제거하고 다음 개발 후보로 채운다. 별도 개발 입력에서 모두
  통과한 후보 중 개발 에너지가 가장 낮은 점을 반환한다. 전부 실패하면 반환하지 않는다.
- 검증 결과는 test가 아니다. 모든 후보 및 반환 설계를 잠근 뒤에만 최종 test를 열었다.
- 기존 모델의 목적은 log-energy expected improvement다. 이를 유지했으며 에너지
  스케일에서의 expected improvement로 바꿨다고 주장하지 않는다.

| 회로 | 검증 없는 조건 | 검증 있는 조건 | seed·조건별 논리적 SPICE 호출 |
|---|---|---|---:|
| ADC | 40설계 × 4입력 | 34설계 × 4입력 + 3설계 × 8검증 입력 | 160 |
| D2D | 24설계 × 4조건 | 18설계 × 4조건 + 3설계 × 8검증 조건 | 96 |

초기 8점과 실패한 시뮬레이션도 비용에 포함한다. 초기점과 같은 prefix는 물리적으로
공유하지만 각 조건의 논리적 비용에 모두 부과했다. 별도 실행기
`experiments/run_validated_search.py`는 실제로 34/18점에서 탐색을 멈춘다.
12개 회로·seed·모델 조합의 저장 측정 재생으로 예산, 후보 및 반환 설계 일치를 검증했다.

실제 추가 SPICE 호출은 1단계 ADC 1,124회(탐색·검증 996, 최종 test 128),
D2D 708회(탐색·검증 564, 최종 test 144)다. 물리적 공유 및 캐시 재사용 때문에
조건별 논리적 비용의 합과 다르다. 실행 시간 동등성은 주장하지 않는다.

## 2. 1단계 최종 시험 결과

ADC는 새 입력 16개 × 3 seed, D2D는 기존 채널의 새 random 패킷 8개와
전이 채널의 새 random 패킷 8개 × 3 seed에서 평가했다. D2D test는 128비트,
128 points/UI다. 1단계 검증은 64비트, 64 points/UI다.

| 방법 | ADC 전체 통과 seed | ADC 입력 통과 | ADC 평균 pJ/sample | D2D 전체 통과 seed | D2D 패킷 통과 | D2D 평균 pJ/bit |
|---|---:|---:|---:|---:|---:|---:|
| 기존 BO | 3/3 | 48/48 | 153.413 | 1/3 | 43/48 | 0.168455 |
| 기존 BO + 64비트 검증 | 3/3 | 48/48 | 153.413 | 2/3 | 45/48 | 0.177978 |
| 최악 제약 GP | 3/3 | 48/48 | 156.021 | 2/3 | 44/48 | 0.170795 |
| 최악 제약 GP + 64비트 검증 | 3/3 | 48/48 | 157.360 | 2/3 | 45/48 | 0.185554 |

**D2D 에너지 열은 실패한 설계까지 포함한 유효 시뮬레이션 평균이다. 품질 통과
설계의 에너지 우위로 읽으면 안 된다.** 실패를 제거한 평균으로 비교군 구성을 바꾸지 않았다.

ADC에서 기존 BO+검증은 세 seed 모두 기존 BO와 같은 최종 설계를 반환했다.
최악 제약 GP의 평균 에너지는 기존 대비 약 1.70% 높다. D2D에서 기존 BO+검증은
전체 통과 seed를 1개 늘렸지만 전체 평균 에너지는 약 5.65% 높았다. 3개 seed만으로
통과율 차이의 통계적 확실성이나 광범위한 우월성을 주장하지 않는다.

## 3. 실패 원인

D2D의 네 방법 모두 전이 채널에서는 24/24개 패킷을 통과했다. 실패는 기존의
더 까다로운 개발 채널(0.95 V, 65°C 쪽)에서 발생했다. 모든 실패 사례의 측정
bit error는 0이었으며, 요구 마진 0.08을 충족하지 못했다. 에너지가 낮다는 이유로
이 결과를 성공 처리하지 않았다.

1단계 기존 BO의 seed 0은 개발 마진 경계 부근의 초기점을 그대로 반환했다.
64비트 검증은 이 후보를 탈락시켰지만 대체 후보도 새 test 패킷에서 실패했다.
seed 2에서는 검증에 의한 선택 변경으로 최종 시험 실패를 피했다.

실패를 surrogate의 과신으로 단정할 증거는 없다. 개발 궤적의 과거 데이터만으로
재구성한 예측에서 0.9 이상 점수가 나온 경우는 ADC 기존 방식의 2건뿐이었고 둘 다
통과했다. D2D에서는 해당 사례가 없었다. 기존 점수는 결합 확률이 아닌 휴리스틱이며,
이 표본으로 확률 보정을 평가할 수도 없다. 확인한 문제는 제한된 개발 패킷의 통과가
미관측 패킷 통과를 의미하지 않는다는 것이다.

## 4. 패킷 길이와 시간 격자의 대조 실험

고정된 test 패킷 하나의 **동일한 두 lane 비트열**을 사용했다. 같은 random seed로
`(2,64)`와 `(2,128)`을 각각 생성하면 lane 1이 바뀌므로, `(2,128)` master를 생성한 뒤
각 lane의 앞 64비트를 잘라 사용했다. 모델·설계·채널·seed를 고정하고 패킷 길이
64/128과 points/UI 64/128을 교차한 16회 추가 SPICE 측정이다.

아래 값은 두 lane의 최소 마진이다. 기준은 0.08이다.

| 고정 설계 | 64비트·64 ppUI | 64비트·128 ppUI | 128비트·64 ppUI | 128비트·128 ppUI |
|---|---:|---:|---:|---:|
| 기존 BO seed 0 | 0.083437 | 0.083482 | 0.068995 | 0.069122 |
| 검증 BO seed 0 | 0.077911 | 0.077939 | 0.071580 | 0.071631 |
| 기존 BO seed 2 | 0.090068 | 0.090130 | 0.075646 | 0.075669 |
| 기존 BO seed 1 — 통과 대조군 | 0.097370 | 0.097440 | 0.093186 | 0.093296 |

시간 격자를 바꿔도 이 사례들의 통과·실패는 변하지 않았다. 두 실패 설계는 앞
64비트에서는 통과하고 뒤 64비트를 포함하면 실패했다. 대체 설계는 새로운 패킷의
앞부분에서도 실패했으므로 **길이 증가만으로 모든 문제를 해결한다고 단정할 수 없다.**
이 실험은 시간 격자보다 패킷 패턴의 검사 범위가 현재 실패의 주된 원인임을 지지한다.

원파형에서도 기존 BO seed 0과 2의 실패가 lane 1의 0-based index 79에서
발생했음을 확인했다. 64비트 평가에는 존재하지 않는 비트다. 대체 후보는
lane 1의 index 10에서도 마진을 놓쳤다. 통과 대조군은 같은 index 79에서 0.09330의
마진을 확보했다. 자세한 값은 `worst_bit_diagnostic.json`에 있다.

## 5. 128비트 검증 후속 실험 — 새로운 시험 패킷

1단계 test를 진단 자료로 사용한 사실을 명시하고 후속 시험 seed를 전부 새로 고정했다.
탐색은 같은 18점 prefix, 후보는 같은 잠긴 세 점을 사용한다. 검증 패킷만 128비트로
늘려 다시 선택했다. 원래 24점 탐색과 64비트 검증의 반환 설계도 같은 새로운
test 패킷에서 다시 평가했다. 반환 설계를 모두 잠근 뒤에만 새 test를 열었다.

| 방법 | 전체 통과 seed | 기존 채널 + 전이 채널 패킷 통과 | 평균 pJ/bit |
|---|---:|---:|---:|
| 기존 BO | 1/3 | 43/48 | 0.163858 |
| 기존 BO + 64비트 검증 | 2/3 | 44/48 | 0.172718 |
| 기존 BO + 128비트 검증 | **3/3** | **48/48** | **0.186033** |

| seed | 기존 BO 에너지 / 전체 통과 | 128비트 검증 에너지 / 전체 통과 |
|---|---|---|
| 0 | 0.166472 / 실패 | 0.220563 / 통과 |
| 1 | 0.172644 / 통과 | 0.172644 / 통과 |
| 2 | 0.152458 / 실패 | 0.164891 / 통과 |

이 표의 기존 방식 평균에는 실패 설계가 포함된다. 128비트 검증은 두 seed의 실패를
피했지만 전체 평균 에너지는 13.53%, 64비트 검증 대비 7.71% 높았다. seed 0에서는
세 후보 중 둘을 탈락시키고 여유가 큰 고에너지 후보를 반환했다. 따라서 **에너지와
품질을 모두 개선했다고 주장할 수 없고**, 유한한 시험에서 품질 실패를 줄인 절차다.

논리적 SPICE 호출은 모든 조건 96회다. 그러나 payload 모사량은 기존 BO의
`24×4×64 = 6,144 bit`에서 긴 검증의 `18×4×64 + 3×8×128 = 7,680 bit`로
25% 증가한다(평가 case별, 고정 warmup 제외; 2개 lane에는 각각 같은 비트 수가 적용됨).
같은 계산량/실행 시간의 비교가 아니며 이 비용 증가를 숨기지 않는다.
후속 시험의 전이 채널 설정은 1단계와 같고 패킷만 새롭다. 채널까지 완전히 새로운
2차 독립 일반화 시험이라고 주장하지 않는다.
후속 단계에서 새로 실행한 SPICE는 검증 72회와 최종 시험 96회다. 16회의 원인 분리
측정까지 포함해 본 실험의 물리적 추가 SPICE는 총 2,016회다. 실행 환경 설치 확인용
단일 입력 측정 2회는 이 수와 별도다.

실행 기본값은 `run_validated_search d2d`에서 기존 BO + 128비트 검증이다.
ADC는 같은 실행기의 기존 BO + 별도 입력 검증을 사용하며 원래 BO 클래스와 단독
탐색 실행기의 기본 동작은 바꾸지 않았다. 최악 제약 GP는 비교용 선택지로 보존했다.

후속 단계는 저에너지 후보를 단순히 더 많이 거절하는 대신, 검증에서 실패한 패턴의
측정을 탐색에 되먹임하여 그 제약을 만족하는 저에너지 후보를 다시 찾는 것이다.
그 방법은 이번에 구현·검증한 것으로 포함하지 않는다. 새 개발/최종 시험 분리와
패킷 길이까지 반영한 비용 비교가 먼저 필요하다.

## 6. 근거와 재현 범위

- 기반 커밋: `aa7cc637500a77436abac56123b3dea9610fff6b`.
- 이번 실행은 ngspice 39를 사용했다. 저장된 종전 D2D pilot은 ngspice 42였다.
  이번 비교 조건은 모두 39에서 새로 측정했으며 종전 발표 숫자와 합치지 않았다.
  공통 초기점의 통과 판정은 종전과 같았지만 미세한 수치 차이가 존재한다.
- `adc/`와 `d2d/`의 protocol, 선택 잠금, summary, seed별 궤적, 검증 결과를 보존했다.
  publication JSON은 ADC의 per-cycle 반복 행을 제외한 compact 사본이다. 원본과 compact
  해시의 차이를 각각 `verification.json`에 기록했다. per-context 지표는 보존했다.
- 원파형은 캠페인 출력에만 있다. 회로 소스, 모델, 실행 파일, Python/NumPy/SciPy 버전 및
  프로토콜은 해시/버전으로 식별한다. compact 자료만으로 원파형을 새로 측정했다고 하지 않는다.
- 관련 단위 검사 7개, 기존 제안 일치 검사, 12개 1단계 및 3개 긴 검증 실행 재생, 동결 소스 및
  반환 규칙 검사를 수행했다. 48개 입력은 48개의 독립 최적화 seed가 아니다.
- 이번 알고리즘 비교의 기준선은 기존 BO다. GA/ALARM까지 같은 새 프로토콜로 재평가한
  결과가 아니므로 모든 기존 방법보다 우월하다는 주장을 하지 않는다.

재현 명령과 단일 예산 제한 실행 방법은 `experiments/README.md`에 있다.
